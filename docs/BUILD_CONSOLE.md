# Free build console

Open `/builds` in Forge Studio. Public run and step monitoring works without a token, subject to GitHub API rate limits. Polling runs only while the tab is visible. Start/cancel/re-run requires a fine-grained GitHub token with Actions read/write and Metadata read for the selected public repositories. The token remains in React memory and is sent directly to api.github.com. It is never persisted by Forge. Reconnect after a reload. No ChatGPT or model credentials are needed.

Forge supports new validation runs, existing Cloudflare deployment dispatch, and one-file local Ollama frontend proposals. GrowthLens/LeadFlow support monitoring and re-running a selected existing workflow at its original commit. A re-run is not a new-source build. Dispatch acceptance is separate from run completion; use the unique marker to match Forge requests to run titles. Do not automatically retry an uncertain dispatch.

`forge-free-build.yml` uses standard ubuntu-latest runners and refuses private repos. No paid AI APIs, larger runners, model cloud fallback, artifacts, schedules, or model caches are added. Inference is qwen2.5-coder:1.5b on local loopback Ollama within the runner, only on manual AI requests. A fresh model download is needed each run. GitHub policies/rate limits can still block work. Existing workflows may have their own storage/cache usage settings.

AI proposals are intentionally limited to a single small existing TSX/CSS frontend file. Paths cannot escape the repo or modify APIs, layouts, the console, dependencies, scripts or workflow configuration. Baseline source tests and production build must pass before inference starts. The model output is parsed, bounded and statically type checked. Generated code is not executed by the proposal job. A passing proposal is committed to `forge-proposal/RUN_ID`; it is not merged, runtime-verified or deployed. Small CPU models are limited and can fail generation/type checks. Workflow success does not mean client readiness or completion of a roadmap item.

A console-source push first verifies source, then deploys through existing Cloudflare secrets to the existing preview URL. Manual validation does not deploy. The existing manual Cloudflare deployment workflow remains available and can publish before final smoke checks finish. API errors, denied Actions permission, missing Cloudflare secrets and failed checks are shown as failures, not fabricated success.
